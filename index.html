Interpretation

Operating Systems Concepts

Virtual Memory

Virtual memory allows a computer to use more memory than is physically available by mapping virtual addresses to physical addresses. The operating system keeps only the actively-used portions of a program in physical RAM, storing the rest on disk.

Pages & Frames

Virtual memory is divided into fixed-size blocks called pages. Physical memory is divided into same-sized blocks called frames. The page table maps each virtual page to a physical frame.

Demand Paging

With demand paging, pages are loaded into memory only when they are actually referenced, rather than in advance. This reduces memory usage and startup time.

Page Faults

A page fault occurs when a program references a page that is not currently in physical memory. The OS must load it from disk, which is a slow operation.

Page Replacement

When all frames are full and a page fault occurs, the OS must choose a page to evict. The choice of which page to replace is governed by a page-replacement algorithm.

FIFO

First-In, First-Out: Evicts the page that has been in memory the longest. Simple to implement using a queue but can perform poorly because it ignores how recently or frequently a page was used.

LRU

Least Recently Used: Evicts the page that hasn't been accessed for the longest time. It assumes that recently-used pages are likely to be used again soon (temporal locality). Harder to implement but typically more effective than FIFO.

Optimal (OPT)

Evicts the page that will not be used for the longest time in the future. This produces the fewest possible faults but is impossible to implement in practice because it requires knowledge of future page references. It serves as a theoretical lower-bound benchmark.

Bélády's Anomaly

For FIFO, increasing the number of frames can sometimes increase page faults — a counter-intuitive phenomenon called Bélády's Anomaly. LRU and Optimal are stack algorithms and never exhibit this anomaly.
